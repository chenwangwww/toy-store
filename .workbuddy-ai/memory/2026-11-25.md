## 修复 CI lint 失败（apps/web）

- 报错：`apps/web/src/components/AuthModal.tsx` 中 `useEffect` 里同步 `setState`，触发新版 react-hooks 规则 `react-hooks/set-state-in-effect`（error，导致 CI exit 1）。
- 修复方式：删除该 `useEffect`，改为 `switchMode(mode)` 辅助函数——先重置 password / confirmPassword / code / message / error，再 `dispatch(setAuthModalMode(mode))`；重置密码成功后的 `setTimeout` 也改用它。
- 结论：`pnpm -r lint` 现在 0 error（剩余 6 个 `<img>` 相关 warning，不阻断 CI）；`tsc --noEmit` 通过。
- 备注：本项目用 Next.js 新版 + eslint-config-next 的 core-web-vitals，effect 内同步 setState 属硬错误，状态重置应在事件处理里做。

## 修复 CI build 失败（Prisma Client 未生成）

- 现象：CI `pnpm build` 中 apps/api 报几十个 `Module '@prisma/client' has no exported member 'PrismaClient' / 'Prisma' / 'User'`，以及大量 `Parameter 'tx' implicitly has an 'any' type`、`Property 'stock' does not exist on type '{}'`。
- 根因：这些全是同一个根因的连锁报错——Prisma Client 是生成产物，未生成时类型全空。`pnpm-workspace.yaml` 的 `allowBuilds` 把 `@prisma/client` / `prisma` / `@prisma/engines` 全设为 false，所以 install 阶段不会自动 generate；本机 `node_modules/.prisma/client` 是之前手动跑过 `pnpm db:generate` 留下的，CI 是干净环境。
- 修复：`.github/workflows/ci-test.yml` 在 `pnpm install` 之后、lint/build 之前加一步 `Generate Prisma Client` → `pnpm db:generate`。
- 验证：本地 `pnpm db:generate` + 根目录 `pnpm build` 三端全部构建通过。
- 注意：全新 clone 的机器同样需要先 `pnpm db:generate` 再 build；若以后在 Linux 上 generate 报缺少 query engine，可把 pnpm-workspace.yaml 里 `@prisma/engines` / `prisma` 改为 true。
