# 2026-10-29

## 项目结构改造：单体 Next.js → pnpm monorepo 三端分离

把原来「用户端 + 后台 + API 写在同一个 Next.js 应用」的项目拆成 3 个子项目，仍在同一个 git 仓库：

- `apps/api`（端口 4000）：纯后端，只保留 `src/app/api/**` Route Handlers + `src/lib/prisma.ts` + `prisma/`（schema/migrations/seed/dev.db）。
  新增 `src/proxy.ts` 处理 CORS（Next 16 起 middleware 改名 proxy，默认 Node runtime），新增 `/api/health`。
- `apps/web`（端口 3000）：C 端，页面 + 组件 + redux store + react-query。
- `apps/admin`（端口 3001）：后台，`/admin/login`、`/admin/toys`，新增 `AdminHeader` 顶栏与根路径 redirect。
- `packages/shared`：三端共用 TS 类型（原 `src/types/index.ts`）。

关键决策：
- 三端只通过 HTTP 通信，前端用 `NEXT_PUBLIC_API_BASE_URL`（默认 `http://localhost:4000`）拼绝对地址；后端用 `CORS_ORIGINS` 控制放行来源。
- 共享类型不通过 `workspace:*` 软链，而是 `tsconfig paths` + `next.config.ts` 的 `turbopack.resolveAlias` 直接指向源码。
  原因：本机 pnpm 安装时无法创建 workspace 软链（isolated 模式依赖装不全），因此 `pnpm-workspace.yaml` 设了 `nodeLinker: hoisted`。
- 根 `package.json` 只放工作区脚本（dev/build/lint/db:*），删掉了根 `next.config.ts`/`tsconfig.json`/`eslint.config.mjs`。

顺带修复：
- 删掉 `src/services/db.ts`（localStorage 假数据库），个人中心改为真实 `GET /api/orders`。
- 登录弹窗改为真实调用 `POST /api/auth`（原来本地伪造随机用户 id，导致下单外键失败）；Redux 登录态在 `Providers` 里从 sessionStorage 恢复。
- 后端 `/api/auth` 返回值剔除 password；`/api/admin/login` 去掉 debug console.log。

验证：`pnpm build` 三端全部通过；`pnpm lint` exit 0（仅剩 warning）；运行时 curl 验证 health/toys/auth/admin-login/CORS 预检均正常。

设计要点（后续如需我落地按此执行）：
- **封禁即时生效的核心**：`requireUser` 改为每次请求回查 DB（`select id/email/isAdmin/bannedAt`），bannedAt 非空 → 401 `code: ACCOUNT_BANNED`。仅靠登录时判断做不到「已登录的退出」。
- 封禁返回 **401 而非 403**：复用 `authFetch` 已有的 401→refresh→失败→clearTokens 链路，前端请求代码不用改。
- 封禁时 `refreshToken.deleteMany({ userId })`，让刷新也救不回来。
- 数据模型：`User.bannedAt DateTime?` + `bannedReason String?`（用时间戳而非 boolean，单字段判断避免状态打架）。
- 接口：`GET /api/admin/users`（分页/搜索/状态筛选）、`GET /api/admin/users/[id]`（详情含 `_count.orders` + `orderAggregate` 累计消费 + 最近 10 单）、`PATCH /api/admin/users/[id]/ban`。
- 约束：不能封自己、不能封 admin（避免锁死后台）。
- **前端补漏**：`auth-client.ts` 加 `setAuthLostHandler`，refresh 失败时通知 Redux `logout()`，否则 localStorage 清了但 UI 仍显示已登录；Providers 加 60s 轮询 + `focus` 事件校验。
- 页面：`/admin/users` 单页 + 详情 Modal，AdminHeader 加导航（商品管理/用户管理）。
