## 项目结构改造：单体 Next.js → pnpm monorepo 三端分离

把原来「用户端 + 后台 + API 写在同一个 Next.js 应用」的项目拆成 3 个子项目，仍在同一个 git 仓库：

- `apps/api`（端口 4000）：纯后端，只保留 `src/app/api/**` Route Handlers + `src/lib/prisma.ts` + `prisma/`（schema/migrations/seed/dev.db）。
  新增 `src/proxy.ts` 处理 CORS（Next 16 起 middleware 改名 proxy，默认 Node runtime），新增 `/api/health`。
- `apps/web`（端口 3000）：C 端，页面 + 组件 + redux store + react-query。
- `apps/admin`（端口 3001）：后台，`/admin/login`、`/admin/toys`，新增 `AdminHeader` 顶栏与根路径 redirect。
- `packages/shared`：三端共用 TS 类型（原 `src/types/index.ts`）。

关键决策：
- 三端只通过 HTTP 通信，前端用 `NEXT_PUBLIC_API_BASE_URL`（默认 `http://localhost:4000`）拼绝对地址；后端用 `CORS_ORIGINS` 控制放行来源。
- 共享类型不通过 `workspace:*` 软链，而是 `tsconfig paths` + `next.config.ts` 的 `turbopack.resolveAlias` 直接指向源码。
  原因：本机 pnpm 安装时无法创建 workspace 软链（isolated 模式依赖装不全），因此 `pnpm-workspace.yaml` 设了 `nodeLinker: hoisted`。
- 根 `package.json` 只放工作区脚本（dev/build/lint/db:*），删掉了根 `next.config.ts`/`tsconfig.json`/`eslint.config.mjs`。

顺带修复：
- 删掉 `src/services/db.ts`（localStorage 假数据库），个人中心改为真实 `GET /api/orders`。
- 登录弹窗改为真实调用 `POST /api/auth`（原来本地伪造随机用户 id，导致下单外键失败）；Redux 登录态在 `Providers` 里从 sessionStorage 恢复。
- 后端 `/api/auth` 返回值剔除 password；`/api/admin/login` 去掉 debug console.log。

验证：`pnpm build` 三端全部通过；`pnpm lint` exit 0（仅剩 warning）；运行时 curl 验证 health/toys/auth/admin-login/CORS 预检均正常。

## 追加：封禁后 C 端 UI 不登出 —— 根因与修复

用户反馈「封禁后 C 端顶部仍显示用户名」。排查结论是三个问题叠加，**不是后端问题**（后端封禁后 `/api/auth/me` 已正确返回 401 `ACCOUNT_BANNED`）：

1. **主因**：`auth-client.ts` 里用模块级变量 `authLostHandler` 存回调。Next dev 的 HMR 会重新加载该模块 → 变量重置为 `null`，而 `Providers` 的 effect 不一定重跑 → `authLostHandler?.()` 成了空操作。
2. **死锁**：`Providers` 的 `check()` 开头 `if (!getAccessToken()) return`。token 被清空后，即使 Redux 里 `user` 还在，后续每次轮询都被门禁挡掉，**永远不会再登出**，界面永久卡在已登录。
3. **触发时机**：监听的是 `window` 的 `focus`，但同一窗口内切换标签页**不会触发** `window.focus`（窗口一直有焦点），从后台切回 C 端时校验没跑。

修复（已落地）：
- `auth-client.ts`：改为 `window.dispatchEvent(new Event('toyland:auth-lost'))`（导出 `AUTH_LOST_EVENT`），彻底避开模块实例问题；`doRefresh` 的「有 access token 但没 refresh token」分支也广播。
- `Providers.tsx`：`addEventListener(AUTH_LOST_EVENT)` 监听；`check()` 门禁改为 `!getAccessToken() && !isAuthenticated` 才 return；轮询 60s → 15s；新增 `visibilitychange`（visible 时校验）。
- 文档 `docs/admin-user-management.md` 第 6 节已同步更新。

经验：**前端"登录态失效"的通知不要用模块级变量存回调**，HMR 会把它清掉；判断是否要校验也不能只看 localStorage，要同时看 store 里的登录态。

## 追加：手机局域网访问打不开（API 地址 + CORS）

现象：手机连同一 WiFi 打开 `http://<电脑IP>:3000`，商品列表空、登录无反应。

根因两条：
1. `apps/web/src/lib/api-base.ts` 回退值是硬编码 `http://localhost:4000`，手机上的 localhost 是手机自己 → 请求到不了电脑。
2. `apps/api/src/proxy.ts` 的 CORS 白名单只有 `localhost:3000/3001`，局域网 IP 来源被拒。

修复（已落地）：
- `apps/web` 与 `apps/admin` 的 `api-base.ts`：改为运行时解析，优先级 `NEXT_PUBLIC_API_BASE_URL` → `window.location.hostname:4000` → `localhost:4000`。因为 `API_BASE_URL` 只用于客户端 fetch（无 SSR 渲染用法），运行时取值安全。
- `apps/api/src/proxy.ts`：新增 `PRIVATE_ORIGIN_PATTERN`，开发环境（`NODE_ENV !== 'production'`）放行 localhost / 10.x / 192.168.x / 172.16-31.x 来源；生产仍只认 `CORS_ORIGINS` 白名单。
- 两个 `.env.example` 把 `NEXT_PUBLIC_API_BASE_URL` 默认值注释掉，并注明「填 localhost 反而会让局域网设备访问失败」。

本机局域网 IP：`192.168.1.129`（WLAN）。
实测通过：`http://192.168.1.129:4000/api/health` 200；OPTIONS 预检回 `access-control-allow-origin: http://192.168.1.129:3000`；GET /api/toys 200 且带 CORS 头；`http://192.168.1.129:3000` 页面 200 且 HTML 中无 localhost:4000 硬编码。

### 真凶：Next dev 的 allowedDevOrigins（不是网络问题）

改完上面两处手机仍打不开，症状是「页面能渲染、商品列表空、按钮点不动」，控制台报 `WebSocket connection to ws://192.168.1.129:3000/_next/hmr failed`。

定位方法：带 `Origin` 头请求 `/_next/static/chunks/*.js` 返回 **403**，不带 Origin 返回 200。即 Next 15.3+ 的 dev 跨源保护：默认只放行 `localhost` 和启动时的 hostname，其他 hostname 的 dev 资源请求一律 403。JS 加载不了 → React 不 hydrate → 页面看着有内容但完全没有交互。

修复：`apps/web/next.config.ts` 与 `apps/admin/next.config.ts` 加 `allowedDevOrigins`：
```ts
allowedDevOrigins: ["192.168.1.129", "192.168.1.*", "10.*.*.*", "172.16.*.*", ...(ALLOWED_DEV_ORIGINS)]
```
注意：只匹配 Origin 的 **hostname**，不写协议和端口；`*` 代表一个 hostname 段；仅开发环境生效。script 标签这类 no-cors 请求不带 Origin，Next 改用 **Referer** 的 hostname 匹配。

验证：改完 Next 会自动重启 dev server，`/_next/...js` 带 Origin 由 403 → 200，仅带 Referer 也是 200，3001 后台同样 200。

排查经验：局域网访问出现「页面出来了但没交互」，先测 `/_next/` 资源带 Origin 的状态码，403 就是 allowedDevOrigins，别再往网络/防火墙方向找。
